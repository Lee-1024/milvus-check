# Prometheus 指标面板实施计划

## 目标

在现有嵌入式 Web 服务中增加 Milvus 专用 Prometheus 指标面板。服务端维护中文指标目录与 PromQL，自动识别 2.5/2.6 指标兼容性，并向页面提供受限的当前值和趋势接口。

## 实施步骤

### 1. 扩展配置模型

- 为 `prometheus` 增加 `job` 配置，默认值为 `milvus`。
- 增加 `metrics.default_range`、`metrics.query_timeout` 和阈值覆盖配置。
- 严格校验时间范围、超时和阈值方向。
- 更新示例配置与配置单元测试。

### 2. 扩展 Prometheus 适配器

- 增加指标名称发现、即时查询、范围查询能力。
- 将 Prometheus 返回值转换为内部向量和时间序列模型。
- 对超时、警告、空结果和类型错误进行明确分类。
- 使用 HTTP 测试服务覆盖正常、空数据和错误响应。

### 3. 实现指标目录与兼容层

- 建立六类中文指标定义、单位、说明、来源和可视化类型。
- 为 2.5/2.6 差异提供按依赖指标选择的查询变体。
- 服务端渲染固定的 `job`、时间范围和 rate window。
- 区分 `available`、`zero`、`no_data`、`unsupported`、`error`。
- 添加默认阈值、中文操作名和目录完整性测试。

### 4. 增加指标 HTTP API

- 增加 `/api/metrics/catalog`、`/api/metrics/summary` 和 `/api/metrics/series/{id}`。
- 只接受目录内指标 ID 和四种时间范围。
- 对汇总查询设置并发上限，单项失败时返回部分结果。
- 确保响应不暴露 Prometheus 地址、凭据或任意 PromQL 输入能力。
- 增加接口契约、非法参数和禁用状态测试。

### 5. 实现嵌入式中文面板

- 保留集合加载表作为首要区域。
- 增加时间范围切换、分类导航、指标卡、趋势图和详情抽屉。
- 嵌入 uPlot 静态资源，不依赖 CDN 或前端构建服务。
- 增加指标字典搜索和缺失、错误、零值状态展示。
- 适配桌面、平板和手机布局，并保证图表固定高度。

### 6. 联调与验证

- 使用当前 Prometheus 实例验证指标发现、当前值和趋势数据。
- 使用当前 Milvus 实例确认集合加载表继续显示全部数据库集合。
- 运行 `go test ./...`、`go vet ./...`、`go build ./...` 和 `git diff --check`。
- 启动预览服务并验证主要 HTTP 路由及页面资源。
