# 集合列表分页设计

## 目标

为 Web 页面“集合加载情况”表格增加客户端分页，避免数百个集合一次渲染导致页面过长。

## 方案

- `/api/status` 继续返回完整集合快照，后端接口不变。
- 浏览器保存当前页和每页条数，只渲染当前页数据。
- 默认每页 `20` 条，可切换 `20`、`50`、`100` 条。
- 集合总数、数据库数和加载状态汇总继续基于全部集合计算。

## 交互

表格底部增加分页栏：

- 显示 `第 1-20 条，共 320 条`。
- 提供首页、上一页、页码、下一页、末页按钮。
- 当前页按钮高亮。
- 首页和上一页在第一页禁用；下一页和末页在最后一页禁用。
- 页码数量受限，只展示当前页附近页码，集合很多时不生成数百个按钮。
- 切换每页条数后回到第一页。

后台刷新时保持当前页。如果刷新后总页数减少，当前页自动收缩到最后一个有效页。没有集合时分页栏隐藏。

## 响应式布局

- 桌面端分页信息、每页选择和页码按钮位于同一行。
- 移动端允许换行，按钮保持稳定触控尺寸。
- 表格现有移动端卡片布局不变。

## 测试

- 静态资源测试确认分页控件存在。
- 前端分页函数覆盖默认 20 条、页码边界、刷新后页码收缩和每页条数切换。
- 运行 `go test ./...`、`go vet ./...`、构建和 `git diff --check`。
